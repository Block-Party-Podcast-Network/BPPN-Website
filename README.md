# Block Party Podcast Network

Static homepage for the network's six Dungeons & Dragons podcasts. Plain
HTML/CSS/JS, no framework, no build step to view the site.

## Why it's built this way

The old site embedded each show's player via third-party widgets
(Spotify/Apple/Podbean iframes). At least one of those (The Titans of
All'Terra) had silently stopped rendering. Investigating showed the show's
RSS feed itself was fine, it was the embed widget that broke.

So this rebuild fetches every show's real RSS feed **server-side** (a small
Node script, not the browser) and writes the result to `data/episodes.json`.
The page then does one same-origin `fetch()` of that JSON at runtime and
builds native `<audio>` players from it. No third-party embed script, no
runtime CORS issues, no dependency on any one platform staying up.

## Local preview

No build step. Just serve the directory statically (a plain `file://` open
also works, since `data/episodes.json` is a same-origin fetch either way on
most setups, but a local server is more reliable):

```bash
npm run serve
# or: npx serve .
```

## Refreshing episode data

Episode data is generated, not hand-written. Run this before every deploy:

```bash
npm run fetch:episodes
```

This resolves each show's feed (directly, or via Apple's iTunes Lookup API
for shows configured with `appleId`), fetches it, and rewrites
`data/episodes.json`. If one show's feed is temporarily down, that show's
previous data is carried over (`lastFetchOk: false` in the JSON) rather than
breaking the whole page - the other five shows are unaffected.

It also runs hourly via `.github/workflows/refresh-episodes.yml`, which
commits `data/episodes.json` only when episode content changed (timestamp-only
changes are ignored). Trigger it manually from the Actions tab if needed.

## Adding a show

1. Add an entry to `data/shows.config.json`:
   - `slug`, `name`, `tagline`, `logo` (path under `assets/images/logos/`)
   - either a direct `feedUrl`, or an `appleId` + a pinned `fallbackFeedUrl`
     (used only if the live Apple lookup fails)
   - `platformLinks` (any of `apple`, `spotify`, `podbean`, `website`, etc.)
2. Save the show's cover art to the `logo` path.
3. Add a matching `<section class="show">` block to `index.html` (copy an
   existing one - it's the static shell with art/name/tagline/platform
   links; the `[data-player-slot]` div inside it is what `main.js` fills in).
4. Run `npm run fetch:episodes` and reload.

## A note on the pinned fallback feed URLs

`fallbackFeedUrl` in `shows.config.json` is a safety net for when Apple's
iTunes Lookup API itself is briefly down or returns something stale, not a
permanent source of truth. If a show migrates hosting providers, the live
lookup will pick up its new feed automatically on the next run - but it's
worth re-verifying the pinned fallbacks every so often so they don't quietly
go stale.

## File structure

```
index.html                   # page shell + hand-authored static content per show
assets/css/styles.css        # single stylesheet
assets/js/{main,render,player}.js   # fetch data, render players, build <audio> UI
assets/fonts/                # self-hosted display font (no external font CDN)
assets/images/{logos,favicon.svg}
data/shows.config.json       # hand-authored: editorial source of truth
data/episodes.json           # generated by fetch-episodes.mjs, committed
scripts/fetch-episodes.mjs   # `npm run fetch:episodes`
scripts/lib/{itunes,xml,normalize}.mjs
```
